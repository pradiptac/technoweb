# C6 API keys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scoped, revocable API keys that let another system read leads, orders, customers, tickets, subscribers and products, and file leads, add subscribers and set stock, through `/api/v1/ext/*`.

**Architecture:** A dedicated `api_keys` table (not Sanctum), an `api.key:<scope>` middleware that authenticates, authorises, throttles and logs, and thin `/ext` controllers whose every record is built by `WebhookPayload` and every write goes through `LeadIntake`, `SubscriberIntake` or `StockLedger`. The console gets System → API keys, mirroring the Webhooks screens.

**Tech Stack:** Laravel 13 / PHP 8.3 / PHPUnit 12 (api), Next.js 16 App Router / TypeScript / Tailwind v4 (web).

**Spec:** `docs/superpowers/specs/2026-10-23-api-keys-design.md`

## Global Constraints

- Version **0.189.0** in `web/src/lib/version.ts` and `VERSION.md` (C4's plan also names 0.189.0; whichever ships first takes it, the other moves up).
- Key format `ak_` + 40 base62 chars; `prefix` = first 11 characters; stored as `sha256` hex, unique index. Never in any resource, log, activity context or URL.
- Header only: `Authorization: Bearer <key>`. A key in the query string is never read.
- Rate limit **120 requests/minute per key**, limiter key `api-key:<id>`.
- Request log retention **30 days**; `last_used_*` written at most **once a minute** per key, through the query builder.
- Lists: `?since=` ISO 8601 on `updated_at`, `?per_page=` 1–100 default 50, ordered `updated_at, id` ascending.
- `/admin/api-keys*` is `role:admin`, in `routes/api/admin-admin.php` beside webhooks.
- No admin request field may be named `key` (`ActivityLogger::CONTEXT_ALLOWLIST` contains `key`).
- Laravel rules from CLAUDE.md: morph map entry `api_key`; relation methods carry generic return types; `@mixin` on resources; `(new Resource($m))->response()->setStatusCode(201)` never `response()->json($resource)`; `composer analyse` says "No errors".
- Frontend: `<Form>` for every Server Action form; `FormActions`; `PageHeader`; `.admin-table` with `data-label` on every `<td>`; `font-mono` for the prefix only; glyphs from `icons-ui.tsx` in client components; dates through `lib/dates.ts`.
- If an API shape changes, `web/mock-api.mjs` changes too.

## Review Focus

- A Sanctum staff or customer token sent as the Bearer on `/ext/*` → 401 `invalid_key`, never treated as a principal. (Task 2 test.)
- `?api_key=<valid key>` with no header → 401; the key is not accepted from the query. (Task 2 test.)
- `?since=yesterday` or `?since=` garbage → 422 on `since`, not a 500 or an ignored filter. (Task 3 test.)
- A stock SKU that matches a product **and** a variation, or two variations → refused for that item ("That SKU is on more than one product."), the rest applied. (Task 4 test.)
- A sensitive ticket read through `/ext/tickets/{ref}` → description and every sensitive message body read `WebhookPayload::REDACTED`; internal notes absent. (Task 3 test.)
