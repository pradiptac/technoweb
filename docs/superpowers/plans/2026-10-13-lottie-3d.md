# Lottie animations and 3D models (0.172.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. The client chose to build straight through, so this plan is task-level. The binding contract is the spec.

**Goal:** Lottie and 3D-model builder sections and layout widgets, with the files in the media library, a pasted link copied into the library, and no third-party request at view time.

**Architecture:**
- **API:** a content checker (`MotionFiles`) in the upload path, an `import-url` endpoint over the existing `MediaDownload`/`storeFromPath`, two section types and two layout widgets.
- **Web:** two client islands, each with a lazily imported library (`lottie-web` light plus `fflate`, and `@google/model-viewer`), wired into `renderSection`, the layout widgets and the console editors.

**Spec:** `docs/superpowers/specs/2026-10-13-lottie-3d-design.md`

## Global Constraints

- No `eval` and no WebAssembly. No security-policy change.
- No request to any host other than the site and the asset origin at view time.
- Both libraries are loaded with dynamic `import()` only.
- The new enum cases are appended at the end of `PageSectionType`, because `PageBuilderTest` asserts the first two.
- `web/` is CRLF; `api/*.php` is LF. Write backslash-bearing PHP with the Edit or Write tool, never a bash heredoc.
- **Probes:**
  - run them with `BASE=http://localhost:3000`;
  - never run one beside an audit, since a sign-in revokes the other's token;
  - throwaway records only, deleted after;
  - no credentials in the probes.
- Never run the PHP suite while another run is using `technoweb_test`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A Lottie whose assets reference an external URL is refused. A `.glb` with an external `uri` is refused.
2. `import-url` with a private, loopback or numeric host, a redirect to one, an oversized file or a wrong extension each answers a 422 on `url`, and leaves no temp file behind.
3. A section whose file was deleted from the library is dropped from the public read.
4. Under reduced motion: Lottie stays on frame 0 and the model has no `auto-rotate`.
5. A `.lottie` with images unzips and renders with no request beyond the file itself.

---

### Task 1 (API): `MotionFiles` and the upload path

- `api/app/Support/Media/MotionFiles.php` is new.
- `MediaUploader`: add the extensions, branch `json`/`lottie`/`glb` to `MotionFiles::check()`, store its `mime` and `width`/`height`, and apply the caps. `StoreMediaRequest` and `storeFromPath()` must not run `mimes:` on these three. `MediaController::replace` stays consistent.
- `meta.library`: the extensions, `max_lottie_kb` and `max_model_kb`. `GET /admin/media` gains `?kind=lottie` and `?kind=model`.
- Tests in `tests/Feature/MotionFilesTest.php`. Fixtures are built in the test:
  - a minimal Lottie JSON;
  - one whose asset points at `https://…`;
  - a `.lottie` zip, made with ZipArchive;
  - a minimal glb, a 12-byte header plus a JSON chunk;
  - a glb with a Draco extension;
  - a glb with an external buffer uri.

### Task 2 (API): `POST /admin/media/import-url`

- The route (with `role:content_manager`), a request class and a controller method, as the spec says.
- Tests in `tests/Feature/MediaImportUrlTest.php`. SafeHttp's resolver is bound per `PublicHost::RESOLVER`, as other tests do, with `Http::fake` for the body. Cover:
  - a public `.json` is stored with 201;
  - a private host is a 422;
  - an unsupported extension is a 422;
  - a content failure is a 422 with the checker's sentence;
  - no temp file is left behind.

### Task 3 (API): sections and widgets

- `PageSectionType` gets `Lottie`/`Model` with `label`/`blurb`.
- `SectionRules` gets `for()` rules, `checkData` media prefix checks (the poster as `image/`), and `normalise()` drops defaults and casts the booleans `loop`/`rotate`.
- `SectionPresenter`: `file`, `format`, `ratio`, `poster`. Dropped when the file is gone.
- `LayoutRules`: the two widgets and the two field kinds. `LayoutPresenter` maps them.
- `PageBuilderTest` provider rows, and a presenter drop test.

### Task 4 (Web): libraries and players

- `npm i lottie-web fflate @google/model-viewer`, then confirm the light build path exists and that model-viewer's ESM entry imports.
- `components/ui/lottie-player.tsx`, `components/ui/model-stage.tsx` and `types/model-viewer.d.ts`.

### Task 5 (Web): rendering

- `types/page-sections.ts` and `components/page-sections/motion-sections.tsx`.
- The `renderSection` cases and the layout `widgets.tsx` cases.
- `mock-api.mjs`: section types, presenter, widget table.

### Task 6 (Web): console

- `MediaBrowser` and `CoverField` get the `kind` prop. `LottiePath`/`ModelPath` with paste-a-link, and `importMediaUrlAction` in `lib/admin/media.ts` plus a server action.
- Section editors and blank defaults. The layout editor's field kinds.

### Task 7: probe, docs, version, audits

- `scripts/probes/motion-media.mjs`, as the spec says.
- Docs, manual, `API.md`, `VERSION.md`/`version.ts` 0.172.0, then `npm run help`.
- Gates: `php artisan test` (alone), `composer analyse`, `tsc`, lint, the probes. Audits of the changed routes in light, dark and mobile.
