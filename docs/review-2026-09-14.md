# Project review — 2026-09-14

A read-only review of the Technoware monorepo (`web/` Next.js 16 + `api/`
Laravel 12) covering code quality, UI/UX, performance and project structure.
**Nothing was changed.** Every finding names a file so it can be acted on
directly; each carries an impact and an effort estimate.

Method: `react-best-practices`, `frontend-design`, `ui-design-system`,
`ui-ux-pro-max` and `laravel-expert` were loaded and used as the checklists;
the codebase was then measured with `grep`/`wc` rather than read for
impressions. Where a count is quoted it was counted. Items CLAUDE.md already
records as deliberate (the icon split, `hidden` attribute vs class, the
console's sub-12px scale, `HIDDEN` in settings-form, the `<datalist>`
comboboxes, `text-white` on the 800/900 bands, the hand-rolled drawer trap)
are excluded.

The two earlier audits — `deep-code-audit-2026-08-27.md` and
`deep-code-audit-2026-09-03.md` — were security and correctness passes. This
one is about maintainability and polish: how much work the next feature
costs, and where the site reads as less finished than it is.

---

## Where it stands

The baseline is unusually clean and worth stating before the list:

- `tsc --noEmit --noUnusedLocals --noUnusedParameters` → **0 errors**;
  **0** `any`, **0** non-null `!`, **0** `@ts-ignore`, **0** `console.log`,
  **0** commented-out code, **0** `!important` in TSX.
- API: **0** `env()` outside `config/`, **0** `dd()`/`dump()`, **0**
  `$guarded = []`, 61 FormRequests, 82 API Resources, 40 enums, 91
  controllers, 70 test files (63 feature / 7 unit, ~25k lines of tests).
- Every route audited passes WCAG AA in light and dark at 320–1920px; the
  audit is CI-gated.

So the findings below are **structural**: files that grew past what one
person holds in their head, primitives that exist and are bypassed, and
copies of one idea in several places. None is a defect a visitor sees today.
All of them are what makes the next change slower than it should be.

## 3. Performance

### 3.1 Server

- **`generateStaticParams` + ISR is in place on every detail route** and the
  cache windows are consistent (25 fetches at 600s, 9 at 300s, 4 at 120s).
  Search bypasses the cache. The redirect table is in memory. The basket
  count is client-fed. This is the part that matters most and it is done.
- **Sequential awaits that could be parallel** (grep found 25 candidates;
  most are `params` + one load and are not waterfalls — these three are):
  - `blog/category/[slug]/page.tsx:64–85` — `getSiteSettings()`,
    `findCategory()` and `publicApi.posts()` are independent and run one
    after another.
  - `careers/[slug]/page.tsx:130–134` — `load(slug)` then
    `getSiteSettings()`.
  - `products/[slug]/page.tsx:67–80` — `resolveProductSlug()` then
    `brands()`; the second does not depend on the first.
  Each is one extra API round trip per cold render (tens of ms against the
  local API, more in production if the API is on another box). → `Promise.all`.
  *Effort: minutes each.*
- **`loading.tsx` exists only for `portal/(app)`.** `(marketing)` and
  `admin/(app)` have none, so a slow dynamic route (`/products/[slug]`, the
  CMS catch-all, every admin list) shows the previous page until the new
  one is whole. A skeleton per area is the `react-best-practices` "strategic
  Suspense" rule at its cheapest. *Effort: an hour for three files.*

### 3.2 Client bundle

- **182 of 580 files are `"use client"`** (31%). Not a problem in itself —
  the console is interactive — but the public site's share should be
  checked: `npm run perf` reports bytes by type per route and is the ruler.
- **`app/portal/(app)/portal-nav.tsx:6–8`** (`"use client"`, customer-facing)
  imports six icons from `@/components/icons` — the whole ~130-icon map
  (47KB / 14KB gz, the figure CLAUDE.md measured). Only `IconBox` is in
  `icons-ui`. → have the server layout pass rendered `<Icon/>` elements in
  the `links` prop, exactly as `lib/navigation.ts` does for the header.
  *Effort: half an hour. This is the one bundle finding a visitor pays for.*
- **Nine console client files import from `@/components/icons` instead of
  `icons-ui`**: `media/item-menu.tsx:5` and `menus/menu-builder.tsx:8`
  (glyphs already in `icons-ui` — one-line change); `media/folder-rail.tsx:8`,
  `media/media-card.tsx:11`, `media/media-preview.tsx:4`,
  `campaigns/block-editor.tsx:7`, `groups/group-manager.tsx:11` (need
  `IconGrid`, `IconLayers`, `IconPen`, `IconSearchChart` promoted);
  `admin-nav.tsx:13` (36 icons — render the nav data server-side once it is
  in its own file, §1.1). `components/admin/icon-field.tsx:4` needs the map
  by design and should be `next/dynamic`-loaded by the forms that use it.
- **`motion/react`** (installed for Velora, ~35KB) is imported by three
  files: `velora/border-beam.tsx`, `dock.tsx`, `vanish-input.tsx`. The beam
  is on every public card, so the library is on every public page. The
  beam animates only while hovered (measured this session), so runtime cost
  is bounded; the download is not. If the bundle figure matters, the beam's
  `offsetDistance` loop and the dock's spring are both expressible in CSS
  (`@property` + `offset-distance` animation; `scale` transitions), which
  would drop the dependency entirely. *Decision, not a defect.*

## 4. UI / UX

Measured against the `ui-ux-pro-max` priority table (accessibility, touch,
performance, style, layout, typography, animation, forms, navigation).
Contrast, tap targets, overflow, headings, canonical and CSP are gated by
`npm run audit` and pass; what follows is what the audit does not measure.

### 4.1 Accessibility (beyond the audit)

- **`chat-widget.tsx:695`** — `<div aria-label="The assistant is typing">`:
  `aria-label` on a `div` with no role is ignored, so the typing state is
  silent to a screen reader. → `role="status"` with an `sr-only` sentence.
- **`portal/(app)/loading.tsx:3`** — same pattern (`aria-busy aria-label`
  on a bare `div`).
- **`chat-widget.tsx:393–397`** — the comment says `role="log"` is "not a
  live region"; `log` has an implicit `aria-live="polite"`. Behaviour is
  probably what is wanted; the comment will mislead the next edit.
- **`site-header.tsx:294–297`** `<li onClick>` and `:427–429` `<div
  aria-hidden onClick>` — both have keyboard equivalents elsewhere; move the
  first onto the `<Link onClick>` so the handler sits on the control.
- **`company/team-grid.tsx:44`** — `<section aria-label={g.name}>` beside a
  visible heading of the same text. → `aria-labelledby`.
- Hover-only affordances: 26 `group-hover:` utilities against 13
  `group-focus*`; roughly half the hover reveals have no keyboard twin.
  Card hover images (`card-images.tsx`) do it right (`focusin`/`focusout`);
  the pattern is there to copy.
- 2 `outline-none` without a `focus-visible` replacement; 3 icon buttons
  with `title=` and no `aria-label`. Small, and the audit's tap-target check
  does not see them.

### 4.2 Responsive layout

- **Breakpoint usage: `sm:` 227, `md:` 25, `lg:` 299, `xl:` 40.** The site
  is designed at phone (< 640) and desktop (≥ 1024) with almost nothing at
  768–1023. A landscape tablet or a half-width desktop window gets the
  phone layout with 1,000px of room — the store grid, the homepage
  sections and the footer columns all wait for `lg` to spread out. The
  audits run at 320–414 and 1280, so the band is unmeasured. → run the
  audit at 768 and 900 once, then add `md:` steps where a two-column layout
  is obviously right (product grids, feature grids, the footer). *Effort: a
  day, driven by what 768 shows.*

### 4.3 Design tokens and consistency

- **Motion durations**: `duration-200` ×71 literal against
  `duration-(--duration-base)` ×14 — the tokens introduced in 0.45.0 have
  fourteen adopters. `duration-300` ×8 and `duration-500` ×6 are the other
  two literal families. → codemod `duration-200` → `duration-(--duration-base)`
  and pick a token for 300/500 (`--duration-slow` exists). One place to tune.
- **Shadows**: the project's scale is `shadow-1/2/3/soft/ink` (73 uses);
  Tailwind's defaults `shadow-lg` ×4 and `shadow-2xl` ×3 leak in. →
  tokenise.
- **Type scale**: 1,800+ arbitrary `text-[Npx]` across **28 distinct
  sizes** (`13px` ×424, `12.5px` ×351, `13.5px` ×243, `12px` ×193, `14px`
  ×109, `11.5px` ×89, `15px` ×85, `11px` ×81, `14.5px` ×47, `10.5px`
  ×35…). `@theme` defines no `--text-*`. The mobile floor in `globals.css`
  has to enumerate escaped arbitrary classes for this reason, and CLAUDE.md
  notes a new sub-12px size is not covered automatically. → define
  `--text-2xs…--text-lg` (10.5 / 11.5 / 12.5 / 13 / 13.5 / 14.5 / 15 / 17)
  and codemod the top ten; the floor then targets named utilities.
  *Effort: half a day; the biggest single consistency win.*
- **Spacing**: `mb-[18px]` ×38 is the `Field` wrapper margin repeated by
  hand where a `Field` is not used; `py-[11px]` ×24 is the control height.
  Both want a token (`--spacing-field`, `--spacing-control-y`).
- **Hard-coded hexes** (CLAUDE.md: "never hard-code a hex"):
  `home/sections.tsx:449` `text-[#a8ada1]` (`--color-dark-muted` exists);
  `sections.tsx:467` and `home/noc-panel.tsx:91` `bg-[#c9993c]/15
  text-[#dcb066]` (a warn-on-dark chip — `--color-warn` has a dark value);
  `sections.tsx:600` and `ui/cta-band.tsx:48` `text-[#cdd6bb]`;
  `blog/blog-sidebar.tsx:228–233` six social brand colours that do not
  respond to the scheme. → `--color-dark-muted-brand`, a `warn-on-dark`
  pair, `--color-social-*`.
- `transition-all` ×32 in 26 files, including `Card` (`ui/card.tsx:36`) and
  the `field` class (`ui/input.tsx:7,83,210`). `Card` wants
  `transition-[border-color,box-shadow,translate]`; the page-level ones
  disappear with the Card refactor (§1.2).

### 4.4 Aesthetic direction (`frontend-design`)

The site has a real point of view — olive/sage brand, Instrument Sans
display over Lora body, hairline borders, generated palettes with a
contrast gate, a restrained motion system with one flourish per surface
(the beam, the flip tiles, the confetti). That is the opposite of generic.
Three places the direction thins out:

- **Section rhythm on the homepage.** Twelve sections in `sections.tsx`
  alternate `bg-page`/`bg-surface`/`bg-dark` bands with the same
  `.section-y` height, so the page scrolls as a stack of equal stripes.
  One or two sections that break the grid — the credentials band already
  does with the retro grid; the case studies could run edge-to-edge, the
  process steps could stagger — would give the page a shape. This is
  editorial, not a defect.
- **The console is denser than the site and says so; the portal is
  neither.** Portal screens use the marketing type scale inside console-shaped
  panels. A one-line decision — portal follows the *site* — would let the
  `.public-site` floor and `.section-y` apply there too.
- **Placeholder art.** 33 SVG placeholders, four invented team members,
  six fictitious clients. Every finding above is smaller than the effect of
  real photography on the client wall and the case studies. Already on the
  must-not-ship list; repeated because it is the largest UI change left.

### 4.5 Forms and feedback

The `<Form>` snapshot-on-refusal, `Field` with `aria-describedby`,
`PasswordField`, `CodeField`, the two live regions for toasts, and
`pending` on the submitting button are all correct and consistently used.
Two gaps:

- Every form's `Button pending` shows a spinner; **long actions** (media
  resize, campaign send, CSV import commit) have no progress beyond it.
  The upload path has a real percentage; the import commit does not.
- Success toasts on `?done=` keys are lookup-only (right). The **cart and
  checkout** use inline `Alert` for refusals and nothing for "added to
  basket" beyond the count badge changing; a toast there is the
  storefront's one missing acknowledgement.
